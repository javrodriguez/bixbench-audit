## Method (E5a's, carried over unchanged unless stated)

- **Rubric in force**: E5a's v0 rubric with addendum 1 (the accept rule: `ideal` is the key; ranges inclusive; numeric keys by half-up rounding to the key's shown precision; text keys trimmed and lower-cased; BixBench's grader recorded, never deciding), addendum 2 section 4 (the unit rule), CHANGES-5 (the three reading groups and the narrow other-scale rule), and **addendum 4 as Javier adopted it** on 30 Sep 2026 at 21:03 EDT ("defaults"): `ADDENDUM-4-PROPOSED-v4.md` sha256 `2fb19ebfb0b58f72e1cfa515551e5d5c03024ec487ce3ee1a5544c38b263cff6`, recorded in force by `ADDENDUM-4.md` sha256 `c10eaa0f0253de8ccb7cd0310d5af779a9c35501337b0ddc859efd7d95da5f46`.
  Its rule applies to E5b questions as written: wrong key needs (a) no accepted pre-registered reading, (b) no in-key reading added after the key that Javier rules defensible, (c) the reference notebook, rebuilt from the data, departing from something the words fix (the variable measured, the groups compared, or a stated denominator or threshold), and (d) the pre-registration's own conditions (a second environment and the named notebook step); a departure only in a choice the words leave open is reword; otherwise undecided; a defect in the reference analysis that does not change the quantity computed is a separate finding.
  Its five readings rulings were about E5a questions and are not extended to E5b; any E5b reading added after a key is seen waits for Javier's own ruling, and every proposal that depends on one says so.
- **Readings from the words, before the key**: for each question the lane reads the question text only (not `ideal`, not the distractors), writes every defensible reading it can name into the script with its convention, and hashes every script into `E5B-SCRIPTS-1.sha256` before any of them runs.
  The keys are read only after the first recorded repetition of all ten.
  A reading added later is labelled with when it was added ("added after run 1", "added after key").
- **No sealed pilot**: E5a sealed its pilot because Javier's pick was still open; here the selection is frozen by this file, so the first runs are the recorded runs.
- **Recorded runs**: each question's script runs twice (repetitions 1 and 2, each recomputing from the capsule data) in the pinned environment, R with `--vanilla` and isolated libraries, Python with `-s -P`, `LC_ALL=C`; outputs, stderr, environment captures and a log with every command, exit status and output hash go to `runs/e5b-recorded-2026-10-01/r{1,2}/`.
  The runner refuses to start unless every script matches its frozen hash, the question file and lockfile match their pins, and every capsule zip and extracted data tree matches its recorded hash.
- **Determinism**: `verify_runs_e5b.py` requires r1 and r2 byte-identical for every output; a difference flags the question "unstable in this environment".
- **Origin check**: after the first recorded repetition, the capsule's reference notebook is extracted and read, and the cell where the key's value arises is named; where it can be rebuilt from the data, an origin script is written, hashed and run twice.
- **Second environment** (needed only for a wrong-key proposal): the package versions the reference notebook records, or an independent implementation.
- **Mutation witness**: for any question proposed wrong key, one planted change to the input that moves the script's value.
- **Proposed verdicts**: one note per question in `notes/E5B-PROPOSED-VERDICTS.md`, citing ids, quoting at most the one key a verdict turns on, each with the BixBench canary line.
- **Adversarial review**: fresh claude-opus-5-5 sub-agents, told to break every proposed wrong key and every undecided (and to test every keep and reword); each round's findings are answered by a dated `E5B-CHANGES` file with probes rerun twice; the loop stops at the first round with no MAJOR.
- **Bank hygiene**: the question file, Verified-50's files, prior-art threads, capsule data and reference notebooks stay git-ignored; `check_no_bank.py` must pass before any commit is pushed; script headers carry ids and readings, never a paraphrase of a question.
